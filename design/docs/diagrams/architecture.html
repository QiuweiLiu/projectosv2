目标与计划 goal / objective

  • 目标状态机：draft → planned → active → completed / failed / cancelled
  • 计划版本化（v1…vn）；草案必须人工确认后才执行
  • 模型只提案：不接受自由文本计划，编译前强校验
  • 继续改进：最多新增 5 个任务、产物全局唯一、已验收任务原样保留
  • 字段语义：artifacts / validators / deps / maxAttempts 强制执行；scope / inputs 仅作提示
  • Workspace 多目标：每个目标独立 projects/<id>、锁与预算，可并行执行

编译与调度 compile / replan / engine

  • compile：计划 → Task + 绑定校验器；DAG 依赖成图
  • 并行执行（默认并发 2），按 maxAttempts 重试
  • 有界重规划：1 次、≤5 个新任务、必须新 ID，不触碰已验收
  • 规范化保护：模型改写已验收结果会被还原
  • 取消 = 协作式请求：写 cancel 标记 → 持锁调度器 Abort 会话
  • 重试继续同一 session，但仍使用新的工作目录；审查/验收始终新会话

验收与交付 verify / review / delivery

  • 三层：确定性校验 → reviewer（有无缺陷）→ acceptance（是否完成需求）
  • reviewer 与 acceptance 是两次独立会话；同版本各限一次；预算覆盖两者
  • 交付：组装 out/ → 在副本上重跑 command 校验 → 写 delivery.md
  • 汇报：模型优先，规则兜底；状态变化使旧汇报失效
  • 执行前审批：高风险任务或 command 校验必须显式 --approve-risk
  • 完成顺序：交付 + 快照都成功后，最后写 completed；失败保持 active 可重跑

planner只读

规划与重规划；只产出计划 JSON。显式 ApprovalMode=default，不会获得 --auto 写权限。

worker可写

在独立任务目录产出产物；--auto 执行；重试续同一会话。

reviewer只读

判断“有没有缺陷”；P0/P1 阻断；不判断需求是否完成。

acceptance只读

判断“是否真的完成任务”；缺需求即阻断；与 reviewer 独立。

reporter只读生成

把状态与 findings 转成中文汇报 / 解释；按输入哈希缓存。

模型解析优先级：CLI 参数 > <state>/models.json > 内置默认；reviewer / acceptance 未设置时跟随 worker。驾驶舱保存到同一份 models.json；模型列表缓存，显式刷新。不内置 provider 凭据，能否使用取决于运行环境的 OpenCode 注册表。
